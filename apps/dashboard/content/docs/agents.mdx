# Agents

Long-running autoresearch campaigns. Connect a **GitHub research repo** (goals and instructions live there), freeze an experiment protocol, and choose GPU compute. The agent discovers datasets from the repo brief and runs comparable trials.

Dashboard: **Agents → Configure agent**. Monitor + chat: open any run from the Agents list.

**Privacy:** AutoRuns, trials, chat, and GPU jobs are private to you. Dataset Agents tabs and MCP `list_auto_runs` / `check_auto` only return **your** agents. Self-hosted GPU runners only claim **your** pending trials.

## How it works

| Layer | Role |
|-------|------|
| Trainfabric control plane | Create the run, bind datasets, enqueue trials, chat |
| Cloud agent sandbox | Clone the repo, load the brief, discover data, propose changes, keep/revert commits |
| GPU trials | **Trainfabric GPU** *or* your **self-hosted runner** — train/eval and report a score |

No SSH. Self-hosted GPUs connect over HTTPS with a runner token.

## Custom GPU (self-hosted runner)

Point any machine with a GPU at Trainfabric:

**Repo:** [github.com/cybertheory/trainfabric-gpu-runner](https://github.com/cybertheory/trainfabric-gpu-runner)

### 1. Register

**Dashboard** — Agents → Configure → Advanced → Self-hosted runner → register a runner (copies `runnerId` + shows the docker command).

**MCP:**

```
register_gpu_runner({ name: "home-gpu", capacity: "gpu:1" })
# → { runnerId, token, docker_run }
list_gpu_runners()
```

### 2. Run on the GPU machine

```bash
git clone https://github.com/cybertheory/trainfabric-gpu-runner.git
cd trainfabric-gpu-runner
docker build -t trainfabric/gpu-runner .
docker run --rm \
  -e TF_API_URL=https://trainfabric-router.rishabhspro.workers.dev \
  -e RUNNER_TOKEN=tfr_… \
  trainfabric/gpu-runner
```

The process claims pending trials, runs your entrypoint, and reports the score.

### 3. Attach to a campaign

**Wizard:** paste the `runnerId` under Advanced → Compute.

**MCP:**

```
start_auto({
  repo_url: "https://github.com/you/research-repo",
  protocol: {
    metric: { name: "val_bpb", direction: "min" },
    budget: { maxTrials: 20, maxWallClockSec: 3600 },
    mutablePaths: ["train.py"],
    immutablePaths: ["prepare.py", "protocol.yaml"]
  },
  compute: { provider: "runner", runnerId: "runner_…" }
})
```

**CLI:**

```
tf auto start --repo-url https://github.com/you/research-repo \
  --compute runner --runner-id runner_… \
  --metric val_bpb --direction min --max-trials 20
tf auto status auto_…
```

Default compute is managed **Trainfabric GPU** (`compute.provider: "trainfabric_gpu"`).

## Repo-first brief

Put the research brief in the connected repo (`TRAINFABRIC.md` → `AGENTS.md` → `README.md`). Keep the eval contract in `protocol.yaml`. The agent loads that after clone.

## Chat

Dashboard chat and MCP `message_auto_agent` / `list_auto_messages` share one thread per run so humans and other agents can steer the same campaign. CLI: `tf auto message <id> --body "…"` / `tf auto messages <id>`.
